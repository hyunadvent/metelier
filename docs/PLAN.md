# Metelier 작업 계획서

> Metelier = Metaverse + Atelier. 귀여운 캐릭터가 가상 화실에 들어가 색칠 게임을 하고, 화실을 꾸미고, 차를 마시고, 책을 읽는 웹 서비스.
>
> 작성일: 2026-11-26 · 참고 이미지: [색칠 화면](reference/coloring-screen.webp), [화실](reference/atelier-room.webp)

## 1. 범위와 우선순위

| 구분 | 내용 | 우선순위 |
|---|---|---|
| 색칠 게임 | 붓을 직접 움직여 물감을 묻히고, 칸 안에서 드래그해 칠하는 게임 | **1순위 (핵심)** |
| 화실 | 캐릭터 입장, 이동, 의자에 앉기, 이젤 클릭 → 색칠 게임 진입 | 2순위 |
| 화실 활동 | 화실 꾸미기, 창가에서 차 마시기, 독서 | 3순위 |
| 계정·저장·멀티 | 로그인, 서버 저장, 다른 사용자와 함께 있기 | 4순위 (MVP 이후) |

색칠 게임이 서비스의 재미를 결정하고 기술 위험도 가장 크므로 **색칠 엔진을 먼저 만들고**, 화실은 그 뒤에 붙입니다.

## 2. 기술 스택 (제안)

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어·빌드 | TypeScript + Vite | 웹 표준, 빠른 개발 서버 |
| 렌더링 | PixiJS v8 (WebGL 2D) | 화실(스프라이트·애니메이션)과 색칠 캔버스(렌더 텍스처·셰이더)를 한 엔진으로 처리 |
| UI (HUD·메뉴) | React | 팔레트 바, 설정, 갤러리 같은 일반 UI |
| 상태 관리 | Zustand | 가볍고 PixiJS와 React 사이 공유가 쉬움 |
| 로컬 저장 | IndexedDB (idb) | 칠하던 그림(PNG)과 진행 상태를 브라우저에 저장 |
| 테스트 | Vitest + Playwright | 엔진 로직 단위 테스트, 붓 드래그 E2E |
| 배포 | 정적 호스팅 (Cloudflare Pages 등) | MVP는 서버 없이 운영 |
| 백엔드 (이후) | Supabase 또는 Firebase | 계정, 클라우드 저장, 갤러리 공유 |
| 멀티플레이 (이후) | Colyseus (WebSocket) | 방 단위 상태 동기화 |

대안: Flutter Web도 가능하지만, 픽셀 단위 마스킹·셰이더·초기 로딩 속도에서 웹 네이티브가 유리해 위 스택을 권장합니다.

## 3. 색칠 게임 설계

### 3.1 요구사항 정리

| # | 요구사항 | 구현 방법 요약 |
|---|---|---|
| R1 | 붓 손잡이를 잡아 하단 물감으로 가져가면 그 색이 붓에 묻는다 | 붓에 손잡이/붓털 두 개의 히트 영역. 붓털 끝이 물감 통과 겹치면 색 장전 |
| R2 | 붓털을 누른 채 드래그해야 칠해진다 | 붓털 영역에서 pointerdown → 칠하기 모드 |
| R3 | 누른 칸 안에서만 칠해진다 | 누른 순간의 칸 ID로 스트로크를 고정, 그 칸의 마스크로 클리핑 |
| R4 | 지나간 부분만, 균일한 색으로 칠해진다 | 원형 스탬프를 경로 따라 찍되 불투명 단색으로 덮어쓰기 (농도 누적 없음) |
| R5 | 번호는 안내일 뿐, 어떤 색이든 칠할 수 있다 | 색 검증 없음. 번호는 표시만 |
| R6 | 칠한 칸 위에 다른 색을 덧칠할 수 있다 | 덮어쓰기 방식이므로 자동 충족 |
| R7 | 완성된 그림을 확인하는 UI | 완성 예시 보기 + 내 작품 갤러리 (5.절 가정 참고) |
| R8 | 확대·축소: 화면 맞춤 ~ 500% | 줌 1.0(화면 맞춤) ~ 5.0, 휠/핀치/버튼 |
| R9 | **색칠 화면은 화실의 이젤에서 칠하는 것처럼 보여야 한다. 화실을 꾸미면 그 꾸민 모습이 캔버스 뒤 배경에 그대로 보인다** (필수) | 색칠 화면 = 화실 장면을 이젤 앞 시점으로 그린 배경 + 이젤 + 캔버스. 3.8절 참고 |

### 3.2 그림 데이터 형식

그림 한 장은 다음 4개 파일로 구성합니다.

```
paintings/cat-basket/
  lines.svg        선화 (확대해도 선명하도록 벡터 권장, 없으면 고해상도 PNG)
  regions.png      칸 ID 맵: 칸마다 고유한 색(=ID)으로 채운 이미지, 안티앨리어싱 없음
  meta.json        칸 목록(ID, 번호, 번호 표시 좌표, 픽셀 수), 팔레트(번호 → 색)
  reference.webp   완성 예시 이미지
```

- 기준 해상도: 2048×1536 (4:3). 500% 확대 시 선은 SVG라 선명하고, 칠은 단색이라 흐려짐이 거의 드러나지 않습니다.
- `regions.png`는 선 아래까지 1~2px 넓혀(dilate) 저장해 선과 칠 사이에 흰 틈이 생기지 않게 합니다.
- **선화는 반드시 닫힌 선이어야 합니다.** 참고 이미지처럼 선이 끊겨 있으면 칸이 서로 새어 나가므로, 제작 단계에서 끊긴 선을 이어 줍니다.

### 3.3 칠하기 엔진

레이어 구성 (아래 → 위): 종이 질감 → **칠 레이어(렌더 텍스처)** → 선화 → 번호 → 붓.

1. **스트로크 시작**: 붓털 끝 좌표를 그림 좌표로 변환 → `regions.png`에서 칸 ID 조회 → 이 스트로크의 대상 칸으로 고정. 선 위나 그림 밖이면 무시.
2. **스트로크 진행**: 이전 좌표와 현재 좌표 사이를 붓 반지름의 1/4 간격으로 보간해 원형 스탬프를 찍음.
3. **클리핑**: 스탬프를 그리는 셰이더가 `regions.png`를 샘플링해 *고정된 칸 ID와 같은 픽셀에만* 색을 씀. 다른 칸으로 붓이 넘어가도 칠해지지 않음.
4. **균일한 색**: 알파 1의 단색으로 덮어쓰기. 여러 번 지나가도 진해지지 않고, 다른 색이면 그대로 교체됨.
5. **지우개**: 같은 방식으로 투명색을 씀 (지우개도 붓처럼 물감 바에서 선택).

붓 굵기는 **화면 기준 고정**으로 둡니다. 확대하면 그림 기준으로는 붓이 가늘어져 작은 칸도 꼼꼼히 칠할 수 있습니다.

### 3.4 붓 조작

| 상태 | 진입 | 동작 |
|---|---|---|
| 대기 | — | 붓이 캔버스 위에 놓여 있음 |
| 이동 | 손잡이를 누르고 드래그 | 붓이 따라 움직임. 칠해지지 않음 |
| 색 묻히기 | 이동 중 붓털 끝이 물감 통에 닿음 | 붓털 색 변경, 물방울 효과, 선택된 물감 강조 |
| 칠하기 | 붓털을 누르고 드래그 | 붓이 따라 움직이며 누른 칸 안에서만 칠해짐 |

- 터치 기기에서는 손가락이 붓털을 가리므로, 칠하기 중 붓털 끝을 손가락보다 약간 위로 띄워 보여 줍니다.
- 물감이 묻지 않은 붓으로 칠하려 하면 물감 바를 흔들어 안내합니다.
- 접근성 보조 옵션(설정): 물감 통을 직접 클릭해도 색이 선택되게 하기. 기본값은 꺼짐.

### 3.5 진행도와 완성

- 색 검증이 없으므로 **칸의 보이는 부분을 100% 칠해야 "칠한 칸"**으로 셉니다 (색 무관).
  - 선에 가려져 보이지 않는 픽셀은 세지 않습니다.
  - 화면 배율에서 보이지 않는 한두 픽셀 때문에 칸이 끝나지 않는 일을 막기 위해, 칸의 0.5% 이하(최대 400픽셀)의 자잘한 틈만 남으면 스트로크가 끝날 때 주변 색으로 메웁니다.
- 상단 `1 / 15` 표시 = 칠한 칸 수 / 전체 칸 수.
- 칸별 칠해진 픽셀 수는 1/2 해상도 비트맵으로 스탬프 때마다 갱신합니다 (매번 전체 픽셀을 읽지 않음).
- 모든 칸이 칠해지면 완성 연출 → 결과 화면(저장, 갤러리로, 화실 벽에 걸기).

### 3.6 확대·축소

- 범위: 1.0(그림 전체가 화면에 맞는 크기) ~ 5.0.
- 입력: 마우스 휠(커서 위치 기준), 두 손가락 핀치, +/− 버튼, 더블탭으로 맞춤 복귀.
- 이동(팬): 확대 상태에서 빈 곳 드래그 또는 두 손가락 드래그. 그림이 화면 밖으로 벗어나지 않게 제한.
- 붓과 물감 바는 화면 좌표에 고정되고, 그림만 확대됩니다.

### 3.7 화면 UI

- 상단 좌측: 홈(화실로 돌아가기), 진행도.
- 상단 우측: 설정(소리, 번호 표시 켜기/끄기, 보조 옵션), 완성 예시 보기, 되돌리기.
- 하단: 물감 바(번호 물감 + 지우개). 색이 많으면 가로 스크롤.
- 진행 중인 그림은 스트로크가 끝날 때마다 자동 저장(디바운스) → 다시 들어오면 이어서 칠하기.

### 3.8 화실 배경과 이젤 (R9)

색칠 화면은 별도의 화면이 아니라 **화실 안에서 이젤 앞에 앉은 시점**입니다 ([참고 화면](reference/coloring-screen.webp)).

- 레이어 (아래 → 위): **화실 배경(꾸민 상태 반영)** → 이젤 → 캔버스(종이·칠·선화·번호) → 붓 → HUD·물감 바.
- 배경은 화실 화면과 **같은 장면 데이터**(배경 + 꾸미기 슬롯에 놓인 가구·소품)로 그립니다. 색칠 화면용 그림을 따로 두지 않으므로, 화실을 꾸미면 색칠 화면에도 자동으로 반영됩니다.
- 이를 위해 화실 장면은 하나의 렌더러(`AtelierScene`)로 만들고, 화실 화면은 방 전체 시점, 색칠 화면은 이젤 앞 시점(카메라 위치·배율만 다름)으로 같은 장면을 그립니다. 꾸미기 소품이 두 시점에서 모두 자연스럽게 보이도록 **에셋은 이젤 앞 시점의 확대 배율을 견디는 해상도**로 준비합니다.
- 줌 100%에서는 캔버스가 이젤 위에 놓여 보이고, 확대하면 캔버스만 커지며 배경과 이젤은 그대로 있습니다.
- 색칠 엔진의 캔버스는 투명 배경으로 그리므로(M1에서 적용됨), 뒤 레이어만 교체하면 됩니다. M5 전까지는 임시 배경을 씁니다.

### 3.9 처음부터 들어 있는 그림 (2026-11-28)

- 언덕 위의 집, 연못의 오리 가족, 하늘을 나는 제비, 빙산 위의 펭귄 가족, 공놀이하는 강아지 (`src/coloring/builtinPaintings.ts`). 이젤을 누르면 이 그림들과 사진으로 만든 그림 가운데 고른다.
- 새 그림은 **선화와 그것을 칠한 완성본 한 쌍**으로 만든다 (`src/editor/fromPair.ts`). 칸은 선화에서 나누고, 칸의 물감 색은 완성본에서 그 칸의 가운데 값으로 정한다 (선 둘레는 보지 않는다). 거의 같은 색(RGB 거리 22 이하)은 한 번호로 묶고, 아주 작은 칸(눈의 반짝이 등, 260픽셀 미만)은 칠하지 않는 칸으로 둔다. 결과 크기는 긴 변 2048.

## 4. 화실(메타버스) 설계

> **방향 변경 (2026-11-27): 화실은 3D로 만든다.** 메타버스에 맞게 [sansatemple.com](https://sansatemple.com/)처럼 3D 공간이어야 한다는 요구에 따른 것이다. 아래 4.1이 현재 설계이고, 4.2의 2D 화실은 보존만 한다.

### 4.1 3D 화실 (현재)

- **기술**: Three.js (WebGL). 코드는 `src/atelier3d/`.
- **시점**: 캐릭터를 뒤에서 따라가는 3인칭 (2026-11-27 확정). 화면을 끌면 둘러보고, 휠로 가까이/멀리 본다.
- **시점은 좌우로 360도 돌릴 수 있고, 캐릭터는 방 끝에서 끝까지 걷는다.** 앞벽에는 문이 있고, 접속하면 문 앞에서 걸어 들어온다.
- **카메라는 항상 방 안에 있다.** 방은 사방과 천장이 막혀 있고, 방 밖은 창문으로만 보인다. 가장 멀리 본 거리는 6.5m 이며(처음 접속했을 때는 5.3m), 벽이나 천장에 닿으면 그만큼 캐릭터 쪽으로 가까워진다.
- **방 구성**: 기획 참고 이미지([화실](reference/atelier-room.webp))를 그대로 옮긴다. 뒷벽 왼쪽에 선반·액자·작업 책상, 가운데에 이젤과 의자, 오른쪽에 큰 창과 커튼, 오른쪽 벽에 책장, 바닥에 깔개와 방석.
- **이동**: 바닥을 누르면 그 자리로 걸어가고, WASD/방향키로도 걷는다. 가구는 둘레를 따라 피해 간다.
- **활동 표시**: 3D 위치를 따라다니는 버튼(이젤, 의자, 창가, 책장). 의자를 누르면 앉고, 앉아서 이젤을 누르면 색칠 화면이 열린다.
- **색칠 화면 배경 (R9)**: 같은 방(`buildAtelierRoom`)을 이젤 앞에 앉은 시점의 카메라로 그린다. 이젤의 캔버스 판이 화면의 종이 자리에 정확히 겹치도록 카메라 거리와 위치를 계산한다. 방을 꾸미면 두 화면에 똑같이 보인다.
- **코드로 만든 에셋** (2026-11-27): 모양은 곡면과 도형의 조합(`shapes.ts`), 텍스처는 캔버스에 그려 만든다(`textures.ts`). 나뭇결 바닥, 벽 얼룩, 깔개 무늬, 책등, 액자 속 그림, 주름 커튼, 잎 달린 화분, 등불의 빛 번짐, 창밖 꽃잎, 구석과 가구 밑의 음영, 가는 갈색 외곽선이 들어 있다. 문 옆 액자에는 완성 예시 그림이 걸린다.
- **아직 임시인 것**: 캐릭터는 뼈대가 없어 팔다리를 축으로 흔드는 동작만 한다. 손으로 빚은 듯한 소품과 수채화풍 질감은 코드로 만들 수 없다. 실제로는 **3D 모델(GLB)** 이 필요하다: 방과 가구, 걷기·앉기 등 애니메이션이 들어간 캐릭터, 꾸미기 소품.
- **활동 (M6, 구현됨)**: 창가 표시를 누르면 찻상 앞 방석에 앉아 창밖을 보며 차를 마신다(5초마다 한 모금). 책장 표시를 누르면 책장 앞에서 책을 고른 뒤 노란 방석에 앉아 읽는다(6초마다 책장을 넘김). 바닥을 누르거나 WASD 로 움직이면 일어난다.
- **꾸미기 (일부 구현)**: 첫 항목으로 **화분 바꾸기**가 들어갔다. 캔버스 오른쪽 받침대의 화분 표시를 누르면 세 가지(초록 잎, 튤립, 선인장) 중에서 고르고, 고른 화분은 저장되어 색칠 화면 배경에도 나타난다. 그 밖의 꾸미기 화면은 아직 없지만, 방은 이미 꾸밈 데이터(`decor.ts` 의 `AtelierDecor`)를 읽어 그린다. 지금은 벽 액자 여섯 자리에 어떤 그림을 걸지를 담고 있고, 브라우저에 저장된다. 화실 화면과 색칠 화면 배경이 같은 데이터를 읽으므로, 꾸미기 화면은 이 데이터를 바꿔 저장하기만 하면 두 화면에 함께 반영된다. 소품 자리(선반, 바닥)를 추가할 때도 같은 데이터에 항목을 늘리고 `buildAtelierRoom` 이 읽게 하면 된다.

**그림 벽 (구현됨)**

- 이젤 왼쪽 벽(방의 -x 벽)을 그림 벽으로 쓴다. 벽의 🖼️ 표시를 누르면 캐릭터가 벽 앞으로 가고 카메라가 벽을 정면으로 본다.
- 완성한 그림(작품집)을 고르면 나무 액자에 넣어 화면 가운데가 가리키는 자리 근처의 빈자리에 건다 (눈높이). 같은 그림은 한 번만 걸린다. 최대 16점.
- 걸린 그림은 끌어서 옮긴다 (둘러보기 대신 그림이 움직인다). 누르면 고른 상태가 되어 "치우기", "다 했어요" 를 고를 수 있다. 치워도 작품집의 그림은 남는다.
- 저장: 꾸밈 데이터(`metelier.decor`)의 `wall` 에 `{ id, paintingId, frame, z, y }` 를 둔다. 그림은 작품집(IndexedDB `gallery`)에서 읽는다.
- **액자 고르기 (구현됨)**: 벽 그림을 누르면 나오는 막대에서 액자를 고른다. 나무 액자(기본), 하얀 액자(반듯한 모서리), 금빛 액자(그림 둘레에 진한 금색 띠), 분홍 액자(아주 둥근 모서리). 고른 액자는 `frame` 에 저장되고 자리는 그대로다. 액자를 늘리려면 `decor.ts` 의 `FRAME_KINDS`·`FRAME_INFO` 와 `room.ts` 의 `FRAME_LOOKS` 에 한 줄씩 더하면 된다.
- 색칠 화면 배경도 같은 꾸밈을 읽어 벽 그림을 건다 (지금의 이젤 시점에서는 왼쪽 벽이 보이지 않는다).
- **남은 결정**: 참고 사이트를 직접 열어 보지 못해(로딩 화면만 확인) 조작 방식과 그림 분위기는 추정으로 만들었다. 사실적/아기자기한 화풍, 다른 방문자 표시 여부는 확인이 필요하다.

### 4.2 2D 화실 (보존)

M5 에서 만든 2D 화실은 그대로 남아 있다. 주소에 `?atelier=2d` 를 붙이면 열리고, git 태그 `atelier-2d` 가 그 시점을 가리킨다. 코드는 `src/atelier/`.

- **표현 방식**: 참고 이미지 같은 고정 시점 2D 일러스트 방. 배경 + 가구 레이어 + 캐릭터 스프라이트.
- **이동**: 바닥을 클릭하면 캐릭터가 걸어감 (보행 가능 영역 폴리곤 + 간단한 경로 탐색).
- **상호작용 지점**: 클릭 가능한 물체에 윤곽선 강조.

| 지점 | 행동 | 결과 |
|---|---|---|
| 의자 + 이젤 | 의자에 앉은 뒤 이젤 클릭 | 그림 선택 → 색칠 게임 |
| 창가 | 차 마시기 | 앉아서 차 마시는 애니메이션, 창밖 풍경·배경음 |
| 책장 | 독서 | 책 읽는 애니메이션, (이후) 그림책/도감 열람 |
| 벽·선반·바닥 | 꾸미기 모드 | 정해진 슬롯에 가구·소품 배치 |

- **꾸미기**: 자유 배치 대신 **슬롯 방식**(벽 액자 자리, 선반 자리, 바닥 자리)으로 시작합니다. 고정 시점 2D 그림에서 어색함이 없고 구현이 단순합니다.
- **색칠과의 연결**: 완성한 그림을 벽 액자에 걸 수 있게 해, 칠할수록 내 화실이 채워지도록 합니다.
- **캐릭터 애니메이션**: 대기, 걷기, 앉기, 그리기, 차 마시기, 책 읽기 (스프라이트 시트 또는 Spine).

## 4.5 사진을 색칠 그림으로 (진행 중)

화실의 문 왼쪽 걸이대에 카메라를 걸어 두고, 카메라를 누르면 사진을 올려 그 사진을 색칠 그림으로 바꾼다.
**변환 로직을 먼저 만들었고**, 화실의 카메라와 올리기 화면은 아직 없다.

### 변환 과정 (`src/photo/`)

| 단계 | 하는 일 |
|---|---|
| 1. 만화풍으로 다듬기 | 윤곽은 남기고 자잘한 무늬와 잡티를 뭉갠다 (양방향 필터) |
| 2. 색 묶기 | 비슷한 색을 물감 수만큼의 묶음으로 나눈다. 색상·채도 차이를 밝기 차이보다 크게 봐서, 작지만 눈에 띄는 색도 번호를 얻게 한다 |
| 3. 칸 나누기 | 같은 색이 이어진 덩어리가 칸이 된다. 너무 작거나 가느다란 칸은 색이 비슷한 이웃에 합치고, 칸 수가 정한 수를 넘으면 작은 칸부터 더 합친다 |
| 4. 선화와 번호 | 칸의 경계를 따라 선을 그린다 (경계에서 만들므로 모든 칸이 닫혀 있다). 묶음마다 원본에서 평균 낸 단색을 번호로 삼고, 넓게 쓰이는 색이 앞 번호다 |

- **얼굴의 눈·코·입은 선으로 남긴다** (`faceLines.ts`). 얼굴을 직접 알아보는 것은 아니고, 살색인 곳을 찾아 한 가지 살색 면으로 만든 뒤 그 안의 어두운 가는 무늬(감은 눈, 눈썹, 콧구멍, 입, 손가락 사이)를 선으로 그린다. 이 선은 칸이 아니어서 칠하지 않아도 된다. 나무나 베이지색 벽도 살색으로 잡힐 수 있어, 사진의 12% 를 넘는 큰 살색 덩어리는 한 면으로 합치지 않는다.
- **가는 어두운 줄은 칸이 아니라 선으로 남긴다.** 벽의 줄무늬, 글씨, 머리카락 가닥처럼 가는 줄이 칸이 되면 칠하기 어렵고, 이웃 칸에 붙어 삐죽 튀어나온 모양을 만든다. 줄은 선화에 그대로 그리고, 칸을 나눌 때는 없는 것으로 친다.
- **실제 윤곽이 없는 경계는 합친다.** 조명 때문에 벽, 그늘, 옷의 주름이 여러 칸으로 쪼개지는데, 그 경계에는 물건의 가장자리 같은 뚜렷한 색 변화가 없다. 경계 길이의 60% 이상에 윤곽이 없으면 그 경계를 없앤다. 이 처리로 선화가 "물건의 윤곽을 딴 그림" 에 가까워진다.
- **같은 색 사이의 윤곽도 잡는다.** 흰 바닥 위의 흰 매트, 흰 옷, 흰 강아지처럼 색이 같은 것끼리는 색을 묶는 것만으로는 경계가 생기지 않는다. 원본 사진을 넉넉히 흐린 뒤(직물 무늬 같은 잔 결을 없앰) 밝기와 색이 변하는 곳을 따라 윤곽을 찾고(Canny 방식), 긴 변의 6% 보다 긴 윤곽만 칸을 가르는 선으로 넣는다. 살색 안쪽과 가는 줄 둘레에는 넣지 않는다 (얼굴 선, 눈금 선과 겹치지 않게). 윤곽이 닫히지 않으면 칸은 나뉘지 않고 선만 남는다.
- **물감 색은 원본의 색을 그대로 쓴다.** 칸 전체의 평균을 내면, 칸 안에 메워 넣은 검은 테두리 선과 경계의 번진 색이 섞여 노랑·민트·파랑이 탁해진다 (그림 원본에서 특히 눈에 띈다). 그래서 원래 그 색 묶음으로 분류된 픽셀만 모아, 원본에서 채널마다 가운데 값을 쓴다.
- **색조가 다른 칸은 경계가 흐려도 합치지 않는다.** 흐릿한 경계를 합칠 때 밝기 차이(조명의 명암)는 합치되, 색조 차이(연분홍과 흰색)는 남긴다. 또 합치는 무리 안의 모든 색이 서로 가까워야 한다: 이웃끼리만 보면 "분홍 → 연분홍 → 흰색" 처럼 조금씩 다른 색이 사슬로 이어져 붓질이 바탕에 통째로 먹힌다.
- 결과는 기존 그림 패키지와 같은 형식이라 색칠 게임이 그대로 읽는다.
- 모든 계산은 브라우저 안에서 하며 **사진을 어디에도 보내지 않는다.**
- 시험 화면: 개발 서버의 `/photo.html`. 사진을 넣어 단계별 결과를 보고, 시험용 그림으로 저장해 게임에서 칠해 볼 수 있다.
- 조절할 수 있는 값: 물감 색 수(기본 14), 칸 수 최대(기본 160), 다듬는 세기(기본 3), 흐릿한 경계 합치기(기본 0.7), 같은 색 사이의 윤곽 잡기(기본 1.0, 0 이면 끔), 가는 줄을 선으로 남기기(기본 켜짐), 얼굴을 선으로 남기기(기본 켜짐).

**화실에서 쓰는 방법 (구현됨)**

- 문 왼쪽 걸이대에 카메라가 걸려 있다. 누르면 사진을 고르는 창이 열린다 (휴대 기기에서는 바로 찍을 수도 있다).
- 사진을 고르면 그 자리에서 변환하고, "색칠할 그림" 과 "다 칠한 모습" 을 나란히 보여 준다. 난이도는 쉽게(10색, 80칸) / 보통(14색, 160칸) / 세밀하게(18색, 260칸) 가운데 고른다.
- "그림 등록하기" 를 누르면 그림을 이 브라우저(IndexedDB `paintings`)에 저장하고 창을 닫는다. 색칠 화면으로 바로 가지 않고, 칠할 그림은 이젤에서 고른다. 사진과 그림은 어디에도 보내지 않는다.
- 사진으로 만든 그림의 이름표는 `photo-` 로 시작한다. 그림을 불러올 때 이 이름표면 서버가 아니라 브라우저 저장소에서 읽는다. 칠하던 내용과 작품집은 다른 그림과 똑같이 저장된다.
- 사진 그림이 한 장이라도 있으면 이젤을 눌렀을 때 그림을 고르는 창이 열린다 (기본 그림 + 사진 그림들). 여기서 사진 그림을 지울 수 있다 (두 번 눌러 확인).
- 그림은 이 브라우저에만 있으므로 다른 기기에서는 보이지 않고, 브라우저 데이터를 지우면 함께 사라진다.

### 한계와 남은 일

- 이미지 생성 AI 는 쓰지 않기로 했다 (2026-11-27): 무료로 쓰기 어렵고 API 연동과 서버가 필요하다. 브라우저 안에서 할 수 있는 최선으로 간다.
- 이 방식은 사진을 **평평한 색면과 윤곽선**으로 바꾸는 것이다. 사람이 그린 듯한 캐릭터 그림(눈을 크게, 선을 단순하게)으로 바꾸지는 못한다. 그런 변환에는 이미지 생성 AI 가 필요하고, 그 경우 사진을 외부 서버로 보내야 한다.
- 남은 일: 화실 걸이대의 카메라, 사진 올리기 화면, 만든 그림을 브라우저에 저장해 이젤에서 고르기, 색이 많을 때의 물감 바 배치.

## 4.6 로그인 (진행 중)

- **둘러보기와 색칠은 누구나** 할 수 있다. 로그인은 화실의 꾸밈과 칠하던 그림을 **다른 브라우저·다른 PC 에서 이어 쓰기** 위한 것이다. 로그인하지 않으면 지금처럼 이 브라우저에만 임시로 저장된다.
- **서비스: Supabase Auth** (2026-11-28 결정). 구글과 카카오 로그인을 둘 다 기본으로 지원하고, 나중에 저장(데이터베이스·파일)도 같은 곳에 둘 수 있다. 설정 방법은 [로그인 설정](LOGIN_SETUP.md).
- **로그인 방법**: 지금은 구글만. 로그인 화면에 카카오는 "준비 중" 으로 보여 준다.
- **화면** (구현됨):
  - 화실 오른쪽 위에 로그인 버튼. 로그인하면 이름과 사진이 보이고, 누르면 로그아웃 메뉴.
  - 로그인하지 않은 채 색칠 화면에서 화실로 돌아가면 "저장하려면 로그인이 필요해요" 창을 띄우고, 로그인하지 않으면 칠한 그림이 초기화될 수 있음을 알린다. "로그인하고 저장하기" / "로그인 없이 화실로 가기". 창을 띄우기 전에 칠한 것은 이미 이 브라우저에 저장해 둔다 (로그인하러 페이지를 떠나도 남는다).
  - 카메라로 사진 그림을 등록할 때 로그인하지 않았으면 "로그인 없이 등록" / "등록하고 로그인하기" 를 고르게 한다.
  - 화분 고르기, 그림 벽 고르기 창에 로그인 권유 띠를 둔다 (꾸미기 화면이 늘어나도 같은 띠를 넣는다).
- **설정이 없을 때**: 개발 서버에서는 개발용 가짜 로그인(어디에도 접속하지 않음), 배포본에서는 로그인 버튼이 "준비 중" 을 알린다.
- **동기화 (구현됨, 실제 Supabase 로는 아직 시험하지 못함)**
  - 맞추는 것: 화실 꾸밈(`metelier.decor`), 칠하던 그림(IndexedDB `progress`), 작품집(`gallery`), 사진 그림(`paintings`).
  - 서버: Supabase 의 `metelier_items` 표(목록과 작은 정보)와 비공개 파일 저장소 `metelier`(큰 파일). [`supabase/schema.sql`](../supabase/schema.sql).
  - 규칙: 같은 것이 양쪽에서 바뀌면 **나중에 바뀐 쪽**을 따른다. 지운 것도 "지운 때" 가 있는 바뀜으로 보고 서버에 남긴다 → 한 기기에서 지우면 다른 기기에서도 지워진다. 계획을 세우는 부분은 순수 함수(`src/sync/plan.ts`)라 테스트로 확인한다.
  - 때: 로그인하면 한 번, 그 뒤로는 이 브라우저에서 바뀌면 2.5초 기다렸다가, 창으로 돌아오거나 인터넷이 다시 연결되면. 실패하면 30초 뒤 다시 해 본다. 로그아웃하기 전에 기다리던 것을 먼저 올린다.
  - **꾸밈은 조각마다 합친다** (2026-11-28): 꾸밈을 한 덩어리로 "나중 것이 이긴다" 로 맞추면, 다른 기기에서 화분 하나만 바꿔도 이 기기에서 건 벽 그림이 통째로 사라졌다. 그래서 화분 자리, 액자 자리, 벽 그림 하나하나마다 바꾼 때를 기록하고(`metelier.decor.stamps`, `src/atelier3d/decorMerge.ts`), 조각마다 나중에 바꾼 쪽을 따른다. 한쪽에만 있는 벽 그림은 남기고, 다른 쪽에서 그보다 나중에 치웠을 때만 없앤다.
  - 받는 차례: 화면에 바로 보이는 것부터 (꾸밈 → 작품 → 사진 그림 → 칠하던 그림), 파일은 4개씩 동시에 받는다. 받는 동안 화실 오른쪽 위에 "저장된 화실을 불러오는 중…" 을 보여 준다. 받은 것은 쓰는 그 자리에서 화면에 알린다 (동기화가 중간에 멈춰도 화면이 놓치지 않게).
  - 처음 로그인하면 로그인 전에 이 브라우저에서 하던 것도 그 사람의 것으로 올린다.
  - 같은 브라우저에서 **다른 사람이 로그인하면** 앞 사람의 그림을 이 브라우저에서 비우고 새 사람의 것을 받는다 (앞 사람의 것은 서버에 있다). 섞여 올라가지 않게 하기 위해서다.
  - 다른 기기에서 꾸민 것을 받으면 화실에 바로 보여 준다. 오른쪽 위 버튼의 메뉴에 저장 상태(저장하는 중 / 모두 저장됨 / 저장하지 못했어요)가 보인다.
  - 개발 서버에서 Supabase 설정이 없으면 "개발용 가짜 클라우드"(브라우저 안의 다른 저장소)에 둔다. 이 브라우저의 저장본을 지우고 다시 받아 보는 것으로 다른 기기를 흉내 낼 수 있다.
  - 한계: 시계가 크게 틀린 기기에서는 "나중에 바뀐 쪽" 이 어긋날 수 있다. 같은 그림을 두 기기에서 동시에 칠하면 나중에 저장한 쪽만 남는다 (칸 단위로 합치지 않는다).

## 5. 가정한 부분 (확인 필요)

1. **"완성된 그림을 확인하는 UI"**를 두 가지로 해석했습니다: (a) 칠하는 중에 보는 *완성 예시*, (b) 내가 완성한 작품을 모아 보는 *갤러리*. 둘 다 계획에 넣었습니다.
2. **1인용으로 먼저** 만들고, 다른 사용자와 같은 화실에 있는 기능은 MVP 이후로 미뤘습니다.
3. MVP는 **로그인 없이 브라우저 로컬 저장**으로 시작합니다.
4. 대상 기기는 **PC와 태블릿 우선**, 휴대폰 세로 화면은 이후 대응입니다.
5. 그림·캐릭터·배경 에셋은 직접 준비하시는 것으로 보고, 저는 형식 규격과 변환 도구를 만듭니다.

## 7. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 붓 조작이 어렵거나 답답함 | M2에서 조작감부터 검증. 붓털 히트 영역을 넉넉히, 보조 옵션 제공 |
| 끊긴 선 때문에 칸 분할 실패 | 제작 도구에서 틈 자동 감지·표시, 선 잇기 기능 |
| 500% 확대 시 칠 가장자리 계단 현상 | 칸 맵을 선 아래로 확장해 가장자리를 선이 덮게 함. 부족하면 칸 맵 해상도 2배 |
| 저사양 태블릿 성능 | 칠 레이어는 스탬프 부분만 갱신, 진행도는 저해상도 비트맵으로 계산 |

| 에셋 제작량 | 출시 시 그림 5~10장으로 시작, 제작 도구(M4)로 추가 비용을 낮춤 |
